# Информационная система учета посещаемости и успеваемости студентов

Дипломный проект: веб-приложение на Python/Django с базой данных PostgreSQL. pgAdmin используется как графический инструмент для создания и просмотра базы PostgreSQL.

## Возможности

- роли пользователей: администратор, преподаватель, студент;
- хранение данных о группах, студентах, преподавателях и дисциплинах;
- электронные журналы преподавателя;
- недельное расписание для групп и преподавателей;
- учет посещаемости по каждому занятию;
- выставление текущих и итоговых оценок;
- электронная зачетная книжка студента;
- личный кабинет студента с результатами обучения;
- адаптивный интерфейс для ноутбука, планшета и телефона.

## Установка

1. Установите Python 3.11+.
2. Установите PostgreSQL и pgAdmin.
3. Создайте в pgAdmin базу данных `diplom`.
4. Проверьте настройки окружения:

```powershell
Copy-Item .env.example .env
```

5. В файле `.env` должны быть такие параметры подключения:

```env
POSTGRES_DB=diplom
POSTGRES_USER=postgres
POSTGRES_PASSWORD=ваш_пароль_от_postgresql
POSTGRES_HOST=localhost
POSTGRES_PORT=5432
```

6. При необходимости поменяйте пароль и параметры подключения в `.env`.
7. Установите зависимости:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
```

8. Создайте таблицы в PostgreSQL:

```powershell
python manage.py migrate
```

9. Создайте администратора:

```powershell
python manage.py createsuperuser
```

10. Добавьте демонстрационные данные:

```powershell
python manage.py seed_demo
```

Дополнительно можно синхронизировать роли пользователей с группами и правами Django:

```powershell
python manage.py sync_roles
```

11. Запустите приложение:

```powershell
python manage.py runserver
```

После запуска откройте `http://127.0.0.1:8000/`.

## Публикация в интернете

Проект подготовлен для деплоя на бесплатной связке Render + внешний PostgreSQL:

- `render.yaml` создает Web Service;
- `DATABASE_URL` можно взять из Neon Free или Supabase Free;
- `build.sh` устанавливает зависимости, собирает статику и применяет миграции;
- Django читает production-базу из `DATABASE_URL`;
- статические файлы обслуживаются через WhiteNoise;
- запуск идет через Gunicorn.

Подробная инструкция находится в `DEPLOYMENT.md`.

## Настольная версия для ПК на C# / WPF

В проект добавлен отдельный красивый десктопный клиент `desktop-csharp/` на C# WPF. Он использует ту же PostgreSQL-базу `diplom` и те же таблицы Django, поэтому веб-версия и ПК-версия работают с общими данными.

Запуск:

```powershell
.\run_csharp_desktop.bat
```

В ПК-версии доступны:

- вход по существующим учетным записям Django;
- современный экран входа и боковое меню;
- панель администратора со сводкой, пользователями, журналами и расписанием;
- управление ролями пользователей;
- справочники для создания групп, дисциплин, пользователей и электронных журналов;
- редактор расписания с созданием и удалением пар;
- журнал преподавателя с созданием занятия, отметкой посещаемости и выставлением оценок;
- раздел преподавателя `Мои курсы` со студентами и занятиями;
- выставление итоговых оценок по курсу;
- кабинет студента с посещаемостью, средним баллом, оценками, журналами и расписанием;
- электронная зачетная книжка студента;
- аналитика учебных рисков и рекомендации;
- поиск по таблицам и экспорт отчетов в CSV.
- встроенные графические ассеты для экрана входа и аватаров ролей;
- панель преподавателя с расписанием дня и быстрыми действиями;
- быстрые массовые отметки посещаемости в журнале;
- автозаполнение итоговых оценок по среднему баллу и посещаемости;
- расписание на сегодня в личном кабинете студента.

Проверка сборки:

```powershell
dotnet build .\desktop-csharp
dotnet run --project .\desktop-csharp -- --smoke-test
```

Сборка exe для демонстрации:

```powershell
dotnet publish .\desktop-csharp -c Release -r win-x64 --self-contained false
```

Готовый запускной файл будет в папке `desktop-csharp\bin\Release\net10.0-windows\win-x64\publish`.

Если проект уже был запущен раньше, после обновления интерфейса все равно выполните:

```powershell
python manage.py migrate
```

Эта команда добавит поле `avatar_url` для аватарок пользователей.

## Демонстрационные пользователи

После команды `seed_demo` доступны учетные записи:

- преподаватели: `teacher1`, `teacher2`, `teacher3`, `teacher4` / `teacher12345`;
- студенты: `student1` ... `student16` / `student12345`.

Администратор создается отдельной командой `createsuperuser`.

## Работа с pgAdmin

В pgAdmin подключитесь к серверу PostgreSQL, откройте базу `diplom` и схему `public`. После команды `python manage.py migrate` там появятся таблицы Django и таблицы предметной области:

- `attendance_profile`;
- `attendance_studygroup`;
- `attendance_subject`;
- `attendance_course`;
- `attendance_studentcard`;
- `attendance_lesson`;
- `attendance_attendancerecord`;
- `attendance_grade`.
- `attendance_scheduleentry`.

Основные данные удобно заводить через встроенную Django admin-панель: `http://127.0.0.1:8000/admin/`.

## Аватары пользователей

У каждого профиля есть поле `Ссылка на аватар`. Его можно заполнить в админ-панели:

1. Откройте `http://127.0.0.1:8000/admin/`.
2. Перейдите в раздел `Пользователи`.
3. Откройте нужного пользователя.
4. В блоке `Профиль и роль` вставьте ссылку на изображение в поле `Ссылка на аватар`.

Если ссылка не указана, система показывает стандартную аватарку по роли: администратор, преподаватель или студент.

## Расписание и права

Администратор может составлять расписание в разделе `Составить расписание`. Пара создается на основе электронного журнала, поэтому группа, дисциплина и преподаватель связываются автоматически.

Раздел `Права` позволяет менять роль пользователя. После выбора роли система автоматически добавляет пользователя в нужную группу Django:

- `Администраторы` — управление пользователями, журналами, расписанием и оценками;
- `Преподаватели` — ведение своих журналов, посещаемости и оценок;
- `Студенты` — просмотр личного расписания, оценок и зачетной книжки.

## Безопасность

Проект использует Django ORM, поэтому обычные запросы к PostgreSQL параметризуются и не собираются вручную из пользовательского ввода. Дополнительно добавлены security headers, CSP, безопасные cookie и ограничение неверных попыток входа.

Подробности и production-настройки находятся в `SECURITY.md`.
